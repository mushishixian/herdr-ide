# Taste
- 用户使用简体中文交流，回复应使用中文（代码、命令、标识符等保留英文即可）。Confidence: 0.8
- 用户会把方案取舍交给助手（"那你做判断"）：期望助手自主做出技术判断并直接执行，不要反复回头请求确认。Confidence: 0.7
- 不要用全局缩放（改 app zoom）来解决跨设备显示差异：用户明确拒绝把 2K 主机 zoom 调到 1.33 去匹配 1080p 的方案（"这么大的字体了，不要这种解决方案"），已要求恢复 zoom 1.0；跨设备"间距不一样"属于分辨率等比观感差，保持默认 zoom，用户想调整时只做针对性修改；用户随后主动追问"可不可以用百分比"，表明其倾向的方向是用 rem/百分比等相对单位改造 UI 元素（如顶栏 gap/text_size），让 UI 按机器独立等比缩放、且不影响终端字号，而不是全局缩放或写死 px。Confidence: 0.85
- 偏好紧凑的 UI 密度：侧栏/面板要窄、树形层级缩进要小（文件树 300→260px、每级缩进 12→8px 就是用户主动要求的）；图标已能表达状态（如开/合文件夹图标）时不要再叠加冗余指示符（三角箭头/chevron）——"有图标了，就不要展示三角箭头符号"。Confidence: 0.85
- 键盘焦点应跟随新打开的交互元素：alt+f12 打开底部终端后用户期望焦点直接落在终端里、可立即打字（"焦点应该在新开的命令行吧，为啥不是"）；实现 open/toggle 类功能时应把"打开即聚焦、可立即输入"作为完成标准并实测验证，只让元素显示出来不算完成。Confidence: 0.75
- 涉及文件路径/外部进程调用的实现必须显式区分 WSL 与 Windows 宿主机，不要默认单一平台：用户明确要求"记住区分是 wsl 还是 windows 宿主机"。本机是 Windows 上跑 app + WSL 工作区的混合环境，拖放等外部事件给的是宿主 Windows 路径（`C:\…`），WSL 工作区需转成 `/mnt/<drive>/…`，`on === null` 表示本机 Windows；给方案和写代码时都要把两个分支都覆盖并分别验证。Confidence: 0.8
- 验证功能是否生效时直接查状态，不要靠 GUI 折腾：用户不接受为了确认一个操作结果去反复开关窗口、截图猜位置（"你就不能直接查看文件是否存着吗?为啥要打开窗口啊"）；应优先用 ls/find/diff、命令输出、日志等直接检查文件系统或应用状态，GUI 自动化只在确有必要时才用。Confidence: 0.75
- 快捷键绑定必须覆盖终端焦点场景：用户几乎总在终端 pane 里打字（编辑器、agent、底部终端都是终端 pane），keys.json 的 global section 绑定在终端聚焦时不生效（git-history 弹窗按 Ctrl+Alt+H 打不开的根因即此，ctrl-tab/alt-f12 是同类先例）；mod 弹窗类快捷键（ctrl-alt-* 家族）须同时在 global 和 terminal section 绑定，但 ctrl-shift-* 刻意不镜像——无 kitty 协议会吞掉 bash 的 ctrl-r/ctrl-f。Confidence: 0.75
